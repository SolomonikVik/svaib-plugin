# Чтение XLSX готовыми скриптами

## Проверка файла

Для каждого XLSX-источника используй путь из описания метрики. Проверь его доступность и дату изменения:

```bash
python3 scripts/snapshot.py local "<путь к книге>.xlsx"
```

`read` возвращает проверенный путь и дату изменения файла; `refuse` — файл недоступен. Дата изменения файла не является датой среза метрики.

## Карта адресов

Выпиши из описания карту — JSON в рабочей папке прогона, **не в пространстве клиента**:

```json
{"year": 2026,
 "source_note": "Книга «…», данные файла от 2026-09-02",
 "metrics": [
   {"name": "MRR", "unit": "AED", "scale": 1000, "sheet": "weekly metrics",
    "labels": ["MRR", "fact (total all)"], "plan_labels": ["MRR", "plan All"]}
 ]}
```

- `labels` — путь меток строки слева направо для карты этого прогона. Найди в книге точное название из паспорта и выпиши метки найденной строки; контекст блока проверь по описанию. Машинный путь не становится обязательным полем паспорта. Нет точного совпадения или выбор неоднозначен — значение не подставляй, предложи уточнение.
- Лист, метки, заголовок колонки и подтверждающая метка ячейки всегда сопоставляются дословно, включая регистр и пробелы. Это действует и для факта, и для плана; старый флаг `strict_labels` больше не ослабляет проверку.
- `scale` — множитель из необязательного поля «Числа в книге». Указано «тысячи» — ставь `1000`. Поля нет или указано «как есть» — ставь `1`: «123» = 123. Отсутствие этого поля не является пробелом паспорта; масштаб по величине числа или денежной единице не угадывай.
- Проценты пересчитывать не надо: код определяет представление по формату каждой ячейки отдельно.
- `expected_row` ставь, если описание называет номер строки — тогда сдвиг будет замечен.

**План:** `plan_labels` подходит для плана на листе факта в той же книге и с тем же масштабом. Для другого листа, книги или масштаба используй `plan_source` в записи основной метрики:

```json
{"name": "MRR", "unit": "AED", "scale": 1, "sheet": "Fact", "labels": ["MRR"],
 "plan_source": {"book": "/путь/к/доступной/книге-плана.xlsx", "sheet": "Budget",
                 "labels": ["MRR план"], "unit": "AED", "scale": 1000,
                 "source_note": "Книга плана, данные файла от 2026-09-02"}}
```

`book` — путь к доступному XLSX-файлу; если книга та же, поле можно опустить. Лист и метки возьми из свободного описания плана и проверь по книге. Масштаб плана определяется отдельно: не указан — `1`, указан «тысячи» — `1000`. Единица после применения масштаба должна совпадать с фактом; её можно опустить, если она та же. Если год плана другой, укажи `year` в `plan_source`. Для одиночного оперативного плана доступны `column_label` и `period`, как у факта.

Читатель сам присоединяет ряд к `plan` этой метрики перед калькулятором. План на будущее не обрезается границей факта. Недоступный адрес или разные единицы — факт сохраняется, план и его производные не подставляются; перенеси пометку. Отдельную метрику «план» для такого соединения не заводи. Это машинная карта прогона; форму плановых данных в паспорте не стандартизируй.

**Оперативное значение — метка плюс колонка.** Показатели вроде «прогноз текущего месяца» или «накопленным итогом» лежат не в ряду по месяцам: у листа есть колонка «Month» и строки, различающиеся меткой блока. Для них вместо ряда указывается `column_label`:

```json
{"name": "Прибыльность, прогноз месяца", "unit": "%", "sheet": "Daily Report",
 "labels": ["MACROREGION", "Profitability forecast"], "column_label": "Month",
 "period": "2026-09", "note": "прогноз на текущую дату, не факт закрытого месяца"}
```

Метка блока в `labels` обязательна: строк «Profitability forecast» в таком листе десяток — по подразделениям, — и без блока получишь отказ со списком кандидатов, а не чужое число. Координаты ячеек в карту не пиши: строки съезжают, метки остаются. Прогноз не смешивается с фактом закрытых месяцев. Известный и существенный для ответа статус периода передай в `note`; читатель сохранит эту пометку. Способ адресации сам по себе не задаёт статус и не требует подтверждать закрытие.

**Прошлый год** — отдельная строка книги (`fact (2025)`) и отдельная запись карты с `"year_offset": -1`: периоды подпишутся прошлым годом. Служебное имя записи карты — строго `{имя основной метрики} год назад`, включая регистр и пробелы: «MRR» → «MRR год назад». Метки строки источника передаются отдельно в `labels`. Калькулятор принимает только один подходящий ряд с нужным периодом и той же единицей; если такого ряда нет или их несколько, сравнение не выполняется и причина сохраняется.

Карта живёт один прогон. В базе клиента машинных файлов не создавай.

## Чтение

```
python3 scripts/read_metrics.py --book <книга>.xlsx --card <карта>.json --json > values.json
```

В `values.json` вернутся строки метрик с периодами, планом, фактом и пометками для общего калькулятора.

## Ограничения штатного читателя

Он читает месячный ряд по меткам либо одиночное значение с проверкой адреса. Для месячного ряда нужна одна однозначная календарная шапка. Год в её строке и над выбранными колонками сверяется с годом карты. Повторяющиеся годовые блоки, даты месяцев и раскладка «месяц × план/факт» требуют отдельной проверки: непонятный год или роль не разрешаются выбором первой колонки. Если скрипт не поддерживает раскладку, выбери другое подходящее чтение. Изменять книгу ради скрипта не требуется.

Reader читает сохранённый числовой результат и не вычисляет формулу заново. Пустая ячейка, ошибка формулы или отсутствие сохранённого результата дают пропуск с причиной. Явные правила описания метрики учитываются при выборе и интерпретации значения.
