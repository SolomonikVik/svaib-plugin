# Подключение аккаунта и продолжение настройки

Читай на первых двух группах после Telegram. Онбординг ведёт этот скилл: техническую подготовку выполняет код рабочего места, установку и вход — штатный механизм выбранного харнесса. Здесь — порядок входа, данные svaib и продолжение.

Начальный помощник появляется у человека после регистрации в Telegram, ещё до компании, BB, другого харнеса и папки. Он объясняет svaib, помогает выбрать и настроить рабочее место, затем передаёт продолжение агенту на компьютере. Не начинай знакомство и установку заново: сначала прочитай тот же профиль аккаунта и доступное общее состояние личной настройки. Выясни только недостающее и веди по одному действию, коротко объясняя его пользу.

Продолжение установки хранится в общем account setup независимо от выбранной компании. Читай его через `get_account_setup`, сохраняй изменённые поля через `patch_account_setup` с прочитанной `expected_revision` и ключом повтора. При конфликте перечитай состояние и сверь факты. Setup содержит ОС, компоненты, сообщённые проверки, блокер и ближайший шаг; фактическую готовность и права проверяй отдельно. Компания, документы, секреты и отметки этапов хранятся вне setup.

## Проверить и восстановить подключение

1. Сохрани работающие агент, модель, профиль и входы. Если MCP доступен, выполни настоящий `whoami` без компании для аккаунта или с точным `company_id` корректной привязки. Доменный отказ компании не означает отсутствия OAuth. Не запускай новый вход ради пройденной карточки.
2. При отсутствии инструментов проверь установленный `svaib-plugin` и конфигурацию MCP штатными средствами текущего харнесса.
3. Если недостаёт авторизации, установи фактические executable, config root и ключ сервера текущего процесса. Для Kimi через Claude Code используй тот же launcher с `--claude`, его `CLAUDE_CONFIG_DIR` и прочитанный ключ, обычно `plugin:svaib:svaib`. Codex использует свой `CODEX_HOME` и точное имя из `codex mcp list --json`, проверенное через `codex mcp get <имя> --json`. Pi использует свой `PI_CODING_AGENT_DIR` и сервер `svaib`.
4. В Pi через BB, если сервер подключён расширением Harness, открой терминал текущего разговора и запусти в том же профиле `pi --no-session "/mcp login svaib"`. Если в конфигурации Pi уже включён сервер `svaib` с адресом `https://api.svaib.com/mcp`, подойдёт `pi mcp login svaib` в том же терминале. Сохрани выбранный адрес и состояние отключённых серверов. В других харнессах используй штатный интерфейс MCP или `mcp login <проверенный ключ>` в терминале выбранного профиля. Человек подтверждает вход в браузере; ссылку, коды и токены не передавай в чат.
5. В исходном разговоре вызови `whoami`. Если инструменты ещё не появились, обнови их штатным способом. В Claude Code и в Pi, запущенном до установки Harness, при успешном входе и всё ещё недоступном `whoami` останови и возобнови провайдер в том же разговоре, затем повтори вызов. После успешного `whoami` закрой созданный для входа вспомогательный терминал Pi.

Если окно авторизации Codex при установке не открылось, было закрыто или истекло, повтори `codex mcp login <проверенное имя>` в том же профиле через терминал. Если CLI не видит сервер, используй штатный интерфейс MCP текущего Codex.

При продолжении после паузы перечитай действительное подключение и свежий прогресс.

## Подключить аккаунт без компании

Аккаунт может существовать без компании. Через штатное подключение MCP вызови `whoami` и проверь контекст ответа. В account-контексте помоги дополнить имя, email и настройки через `update_me`; company-контекст используй как профиль членства выбранной компании. Данные аккаунта и участника читай и дополняй отдельно. Путь к локальному профилю и трек компании относятся к проверенному членству в ней.

Если компаний нет, помоги создать реальную компанию по поручению или принять приглашение коллег. Приглашение принимай только с предъявленным кодом через `accept_invite`.
