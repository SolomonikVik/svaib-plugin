# Компания, папка и начало работы

Читай перед выбором компании, привязкой папки или подготовкой каркаса.

## Три независимые проверки

| Цель | Что проверяется | Маршрут |
| --- | --- | --- |
| Работать с агентом в выбранной папке | Реальные читаемые файлы и привязка к выбранной компании, когда нужна серверная работа | Существующие материалы; для каркаса — `space-scaffold` |
| Работать с файлами через серверного партнёра в Telegram/почте | Подключённый источник и успешное серверное обновление | `references/drive.md` или `references/git.md` |
| Обмениваться изменениями и работать с коллегами | Настроенный обмен файлов и права каждого участника хранилища | Справка выбранного хранилища; приглашение в svaib отдельно |

Локальное чтение не доказывает серверный доступ; `ready` серверного источника не доказывает обмен изменениями с локальной папкой. `not_connected` говорит об отсутствии источника для серверного партнёра и не требует ремонтировать готовый локальный каркас. Если цель известна, веди по ней; иначе уточни, какой результат нужен.

Сначала проверь объявленную папку и существующие материалы. Онбординг ведёт агент; конструктор — необязательный инструмент ввода и вывода. Если человек выбрал его, используй общий серверный Screen для настоящей компании с проверенным доступом: подходящий сохранённый экран открывай повторно, устаревший снимок предлагай обновить с прежним ID. Общий Screen рассчитан на браузер и адаптеры разных сред; используй фактически доступный канал установленной версии. Отсутствие доступного канала показа назови ограничением; оно не блокирует создание каркаса через разговор и `space-scaffold` и не требует смены рабочего места или повторной регистрации.

Screen возвращает намерение человека, сохранённое состояние и границы данных. Агент обсуждает результат, отдельно согласует файловые изменения и выполняет их со `space-scaffold` в объявленном корне. Ни неподтверждённый статус, ни различие версии шаблона и структуры сами по себе не запрещают работу. Перед записью проверь актуальное намерение и состояние файлов; при техническом конфликте перечитай данные и согласуй изменившееся, не требуй пересоздать пространство. Каркас считается созданным по проверенным файлам, а не по JSON или клику «Готово».

Обычное поручение прочитать или подготовить доступные локальные файлы не требует выдуманной компании или MCP-входа. Это не альтернативная локальная реализация Screen и не свидетельство серверных прав. Без серверного статуса отвечай по наблюдаемым фактам и одному следующему действию; не заводи локальные marks, каталог или копию общего setup. Существующую привязку не исправляй и не обходи автоматически.

## Привязать папку к компании

Этот раздел — для выбранной реальной компании; серверные операции используют её контекст. Обычные локальные файловые поручения этой привязки не требуют. Используй сборку плагина для выбранного приложения. Проверка MCP-входа и проверка работы company/map хуков — отдельные шаги инструкции подключения; не меняй host-настройки по догадке во время онбординга.

Один человек может работать с несколькими компаниями. Папка пространства привязана к одной из них файлом `.svaib/platform.json`; выбор компании в Telegram или другом чате эту привязку не меняет.

- **Привязка уже есть:** вызови `whoami` для этой компании через обычное подключение MCP. Права проверяет сервер. Если файл повреждён или компания недоступна, останови операции серверной компании и назови причину; не выбирай другую компанию и не ищи привязку выше ближайшей `.svaib/`. Порученную локальную работу можно продолжить в объявленной папке без изменения привязки.
- **Привязки нет:** через то же подключение MCP вызови `list_my_companies`, покажи доступные компании и получи явный выбор. Если человек поручил создать компанию, используй `create_company` и полученный стабильный ID. Не подставляй название или первую компанию из списка.
- **Папка готова:** передай выбранный ID локальному `scripts/bind_company.py`: `python3 "<каталог этого скилла>/scripts/bind_company.py" --root "<абсолютный путь к папке пространства>" --company-id "<ID>"`. Скрипт пишет только привязку в ближайшую существующую `.svaib/`; если каркаса ещё нет, его разворачивает `space-scaffold`. Токен и адрес сервера скрипту не нужны.
- **После записи:** вызови `whoami` с выбранной компанией и проверь ответ. Файл переносится вместе с папкой; `space.json` и подключение MCP не меняй.
- **Перепривязка:** сначала покажи прежнюю и новую компании и получи явный выбор человека. Передай прежний ID через `--rebind-from "<прежний ID>"`; если привязка уже изменилась, перечитай её и согласуй выбор заново. Устаревший `--rebind-from` отвергается и при повторе команды после успешной замены; обычный повтор записи того же ID без этого аргумента ничего не меняет. После успешной замены открой новый чистый чат до работы с другой компанией. Pin старого разговора не удаляй и не сбрасывай, даже после закрытия приложения.
