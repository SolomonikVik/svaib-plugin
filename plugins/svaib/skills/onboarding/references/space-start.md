# Компания и подключение её пространства

Порядок задаёт раздел «Пространство компании» в `references/onboarding.md`. Здесь — проверки доступа, привязка папки и справки для операций этого маршрута.

## Найти общее пространство

Используй компанию из явного выбора человека; доступ проверь через `whoami(company_id)`. Если компания ещё не выбрана, покажи `list_my_companies`. Создание отдельной компании — по поручению человека.

Проверь доступные материалы выбранной папки. Адрес git можно узнать из `workspace.repo` в ответе `whoami`. Для сведений об общем источнике используй `get_tenant`, если он есть в `capabilities` выбранной компании. Если источник неизвестен, уточни у человека, где уже хранится пространство. Пустая папка, пустой адрес git и статус `not_connected` сами по себе не подтверждают отсутствие общего пространства.

При отсутствии доступа объясни, какой доступ запросить у владельца. Проверь контакт через `list_users`, если он есть в `capabilities`. Если контакта нет, предложи обратиться к тому, кто пригласил человека в компанию.

Для файлов и синхронизации читай `references/drive.md` или `references/git.md`. Для доступа Telegram-ассистента используй маршрут серверного источника из справки. Для приглашения читай `references/stage-actions.md`. Проверь выданные права на файлы и передачу приглашений. Принятие приглашений проверяй отдельно от продолжения онбординга владельца.

## Проверить выбранную папку

Читаемые актуальные файлы, компания в `.svaib/platform.json` и работающая синхронизация — разные наблюдаемые факты. Проверь нужное для поручения. Если требуется проверка обмена изменениями, используй процедуру выбранного хранилища; проверка локального чтения её не заменяет.

Если привязка уже есть, используй её компанию; повреждение или несовпадение сначала разбери с человеком. Не ищи другую привязку выше ближайшей `.svaib/` и не меняй её молча. Порученную локальную работу можно продолжить без изменения привязки.

После успешного `whoami(company_id)` для готового пространства без привязки используй локальный помощник: `python3 "<каталог этого скилла>/scripts/bind_company.py" --root "<выбранная папка>" --company-id "<выбранный ID>"`. Он пишет только `.svaib/platform.json`. При согласованной смене компании передай прежний ID через `--rebind-from` и проверь ответ. Работа с другой уже закреплённой компанией начинается в отдельном чистом разговоре.

Локальные пути, проект и настройки приложения остаются на компьютере. В MCP не передавай их как источник компании или сведения профиля. Общий адрес git / Google Диска — свойство хранилища компании; он не задаёт локальную папку клиента. Отметку подключения ставь по проверенным признакам, без копии локальной конфигурации.
