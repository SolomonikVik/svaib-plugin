# Прогресс и отметки

Читай при входе в онбординг и перед записью прогресса. Признаки этапов и форма ответа — `references/onboarding.md`, каталог — `references/stages.json`. Первые четыре группы и их приоритет задаёт входной `SKILL.md`.

Серверный статус — на платформе svaib. Контекст определяй по ответу `whoami`: `account` — профиль аккаунта, `company` — профиль членства выбранной компании. У каждого свой `onboarding` (`marks`, `audience`, `tools`, `reviewed_catalog`). В папке пространства хук подставляет компанию её привязки. Владельцу `get_tenant` отдаёт прогресс компании, `get_user` — статус сотрудника. Читай статус перед работой и сохраняй отметки в том же контексте: подсказка на старте сессии берётся из кэша и может отставать на сутки.

## Путь человека

После проверки серверной личности и доступа путь собирается каждый раз: каталог × кто человек × отметки. Локальные файловые поручения до подключения выполняются без серверных отметок и не требуют пройти серверные зависимости каталога. Отдельного локального каталога и хранимого личного плана нет.

- **Применим:** `track` = `user`, `active`, `audiences` пуст или содержит `audience` человека, этап базовый или выбран в `tools`. Нет `audience` — владелец считается `ceo`, остальные `employee`.
- **Пройден:** отметка `done` на своём id или на любом из `replaces`. Явная отметка на новом id важнее наследованной; зачёт через предшественника показывай с его названием и новой отметки не ставь.
- **Следующий после первых четырёх групп:** первый по `order` из применимых непройденных, не `skip`, у которого пройдены все `requires`.
- **Незнакомый id** в отметках пропускай и не трогай: его поставил более новый плагин.

Для `company`-этапов проверяй активность, зачёт и зависимости; следующий этап выбирай по задаче компании. Показывай владельцу «пройдено N из M». Владелец просит путь сотрудника — расчёт пути человека над `get_user`.

## Результат

- **«Где я остановился»** — по форме из `references/onboarding.md`, одно следующее действие. Полный путь — по «покажи мой путь». Человеку — названия этапов, не id и не имена вызовов платформы.
- **Новое в каталоге** — `reviewed_catalog` меньше `catalog`: объясни изменения по записям `changelog` с номерами выше `reviewed_catalog`, предложи новое, запиши `reviewed_catalog`. У нового человека объяснять нечего — просто запиши номер. Объяснение этап не проходит.
- **Шаг этапа** — по поручению пройти онбординг или отдельный этап, по справке своего этапа; работу этапа, у которой есть свой скилл, делает он. Следующее разрешённое действие выполняй сам; сведения и необходимые согласия получай одним конкретным вопросом. Шаги, которые может сделать только человек, — по одному, с проверкой после каждого.

## Отметки

- Данные setup и локальное развёртывание сами по себе не ставят серверные отметки `user.connect`, `user.space` или `company.launched`. После настоящего подключения заново проверь личность, применимость, зависимости и признаки существующего этапа; только затем используй обычную запись. Новые локальные ID этапов и файлы отметок не заводи.
- **Только после проверки признака закрытия, применимости и зависимостей.** Признак подтверждает наблюдённый результат — шаг выполнен и проверен в этом разговоре, — артефакт в пространстве или строка учёта использования (`.svaib/usage/`) с проверенной принадлежностью человеку: `кто` сопоставлен с его `subject`. Учёт поддерживается в Claude Code и Codex; строка появляется с задержкой, к следующему запросу или концу сессии. Это один из источников, а не обязательный.
- **Состояние:** достаточного свидетельства действительно нет — `unverified`; шаг за другим человеком — `waiting` с `reason` и `actor`; человек решил позже — `deferred`; этап ему не подходит — `skip`.
- **Запись** — `update_me` с аргументом `onboarding.marks` и ключом повтора. В `expect` всегда передавай состояние отметки, которое ты прочитал (`null` — отметки не было), а меняя `audience` или инструменты — и их прочитанные значения: так чужая запись между чтением и записью не затрётся. Отказ `onboarding-conflict` — возьми текущее состояние из ответа, покажи человеку, вслепую не повторяй. Что отметил — скажи одной строкой.
- **Этап компании** отмечает только владелец: `update_tenant` с той же формой `onboarding`. Не владелец сделал шаг компании — скажи, что этап отметит владелец. Если один шаг выполнил признаки и этапа человека, и этапа компании — например, первый разбор встречи владельца, — владелец ставит обе отметки.
