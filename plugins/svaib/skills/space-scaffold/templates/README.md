# templates — шаблоны scaffold

Единый источник шаблонов scaffold. `root/` — корень нового пространства, он копируется при развёртывании; остальные шаблоны читаются отсюда, когда заводится узел или файл, и в пространство не копируются.

## Словарь разворачивания

Эти термины нужны агенту-строителю, чтобы не потерять архитектурную точность при разворачивании. В живом scaffold клиента используем русский рабочий язык.

- **Объект управления** (management unit) — то, чем компания управляет как отдельным целым: компания, направление, продукт, филиал, клиентский портфель. Объект — всегда папка.
- **Ракурс управления** (management aspect) — сторона, через которую смотрим на объект управления — стратегия, цели и показатели, команда, финансы, проекты, процессы, ритм управления.
- **Обзорные файлы** — файлы `_` в папке объекта: вводная, делаем, планы, хроника, решения. **Папки управления** — папки `00_` по ракурсам. **Обычные папки** — что компания заводит сама. **Файл навигации** — `README.md` папки.
- **Node / узел** — управляемая сущность в дереве: файл или папка, которая может расти.

## Рабочее имя в живом файле

Перед копированием шаблонов определи рабочее имя субъекта: как этот объект должен называться в клиентском тексте и поиске.

- Источник имени — клиент, не агент. Имя неизвестно → спроси. Спросить нельзя → временный slug с нумерацией (`project-01/`, `project-02/`); агент имя не выдумывает. Slug переименовывается, когда имя появится.
- Шаблон назван так же, как файл или папка в пространстве; латиницей остаются группы шаблонов (`root/`, `aspects/`, `nodes/`…) и виды узлов с именем клиента (`nodes/unit/`, `nodes/employee/`, `client-name/`). Свою папку называет клиент (`продажи/`, `маркетинг/`); папка и профиль сотрудника — по имени и фамилии: `иван-петров/`.
- Живой текст пишется рабочим языком клиента: `Продажи`, `Маркетинг`, имя человека, название клиента или продукта.
- Класс-термин сущности («направление», «функция», «блок», «отдел») тоже бери из языка клиента, а не подставляй шаблонный: клиент называет всё «направлениями» — пиши «направление», не «функция».
- `title`, H1 и аннотация под H1 вместе задают миссию файла. Специализируй все три.
- Generic-слова из шаблона (`узел`, `unit`, `client-name`) не оставляй в живом файле, если субъект известен.
- Чистая автозамена плейсхолдера недостаточна: аннотация должна нормально читаться человеком и быть очевидной в поиске.

## Содержимое папки

- [nodes/](nodes/) — шаблоны узлов: `unit/`, `product/`, `clients/`, `employee/`. Читать: когда нужно создать новый узел (направление, продукт, клиента, узел сотрудника).
- [management-kit/](management-kit/) — шаблоны обзорных файлов: вводная, делаем, планы, хроника, решения. Читать: когда объекту нужен обзорный файл.
- [semantic-files/](semantic-files/) — шаблоны типовых смысловых файлов: паспорт, архитектура, глоссарий и др. Читать: когда узлу нужен устойчивый смысловой файл.
- [aspects/](aspects/) — шаблоны папок управления. Читать: когда объекту нужна папка управления.
- [_встречи/](_встречи/) — шаблон служебной папки для памяти встреч узла. Читать: когда узлу нужны `_встречи/`.
- [база-знаний/](база-знаний/) — шаблон обычной папки `база-знаний/`, не папка управления. Читать: когда узлу нужна база знаний.
- [infrastructure/](infrastructure/) — шаблоны служебных папок `_входящее/` и `_архив/`. Читать: когда узлу нужно место для неразобранного или архив.

## Как развернуть узел

Объект управления — всегда папка: в ней с первого дня файл навигации `README.md` и `_вводная.md`, остальное — по ходу работы. У компании вводной нет: её роль играют видение, цели и стратегия. Часть бизнеса, которой пока не управляют отдельно, — не объект: строка в README или файл родителя, пока у неё не появятся свой ответственный и своя работа.

Новый узел (направление, продукт, клиент, узел сотрудника) — копией из [nodes/](nodes/):

1. Скопируй папку нужного типа из `nodes/{type}/` на её место в дереве.
2. **Переименуй папку под сущность.** Имя шаблона ≠ имя живого узла:
   - `nodes/unit/` → имя объекта управления: `маркетинг/`, `продажи/`, `филиал-красноярск/`
   - `nodes/employee/` → имя сотрудника: `иван-петров/`. Профиль `иван-петров.md` переезжает в узел как `профиль.md`; профиля не было — копия [aspects/00_команда/имя-фамилия.md](aspects/00_команда/имя-фамилия.md). Ссылку на профиль в `оргструктура.md` переведи на `иван-петров/профиль.md`
   - `nodes/продукт/` → `продукт/` (или `продукт/{имя}/` при нескольких продуктах) — не отдел разработки (тот — обычный unit из `nodes/unit/`)
   - `nodes/клиенты/` → `клиенты/`, внутри `client-name/` → именем клиента

3. Поправь `title`, H1, аннотацию под H1, локальные ссылки и строки `## Содержимое папки` во всех файлах узла под рабочее имя (`продажи/` → «Продажи», `иван-петров/` → Иван Петров, `client-name/` → название клиента).
4. Создай стартовую `_вводная.md` узла — копией из [management-kit/_вводная.md](management-kit/_вводная.md), субъект → имя узла. Это точка входа узла; в шаблоне узла её нет (шаблон вводной один в папке шаблонов). Исключение — `nodes/employee/`: точка входа — `профиль.md`, отдельная вводная не создаётся. Разворот `nodes/клиенты/` создаёт два узла сразу — портфель `клиенты/` и папку клиента: шаги 3–6 применяй к каждому, `_вводная.md` получают оба. Блоки «Условия» и «Важно знать» — по желанию: нечего записать — удали блок.
5. Впиши узел строкой в `## Содержимое папки` README родителя.
6. Доразворачивай остальное содержимое узла (обзорные файлы, папки управления, служебные папки) по правилам ниже — только под живую работу.

Шаблоны узлов `nodes/` тонкие: README + узловые файлы, уникальные для типа узла (`продукт/паспорт`, `клиенты/client-name/компания`). Универсальные файлы (вводная, остальные обзорные файлы, папки управления) берутся из папки шаблонов. По умолчанию `AGENTS.md`/`CLAUDE.md` в узлы не ставятся — вход агента живёт в корне пространства; в папке шаблонов их нет.

## Как развернуть файл или папку

Перед созданием `README.md` определи класс папки:
- Узел из `nodes/` получает `README.md`.
- Папка управления получает `README.md` только если его шаблон уже содержит README (`00_показатели/`, `00_финансы/`, `00_проекты/`, `00_процессы/`).
- Простые папки управления `00_стратегия/` и `00_команда/` README не получают: навигация живёт в родительском README и самих файлах.
- Личную территорию сотрудника разворачивай как `_личное/` внутри его узла в `00_команда/`; других `_личное/` нет. README создавай, когда путь и видимая структура не дают агенту достаточной навигации. Права доступа настрой средствами выбранного хранилища до размещения материалов.

1. Найди шаблон в нужной группе выше.
2. Скопируй в узел. Папку-шаблон не копируй целиком: создай папку, скопируй её README и только фактически разворачиваемое содержимое; элементы, перечисленные в `## 🔧 Разворачивание`, не копируй до их триггера. Имя шаблона замени итоговым по таблице «Миссия файла»; имя с `{...}` — под сущность: `имя-фамилия.md` → `иван-петров.md`, `показатели-направления.md` → `показатели-продаж.md`, `процесс.md` → `найм.md`. Переименовал файл — поправь и `title`/H1 внутри (`{Имя Фамилия}` → `Иван Петров`).
3. Специализируй шапку файла под рабочее имя: `title`, H1 и аннотацию под H1. Затем заполни плейсхолдеры внутри (`{node}`, `{topic}` и даты событий там, где они стоят в теле файла) и поправь пути: записанные от корня scaffold (например, `00_компания/00_показатели/ключевые-показатели.md`) пересчитай под фактическую глубину узла. Данных для секции пока нет — напиши «секция будет заполняться по мере поступления данных» вместо плейсхолдера; секцию, не нужную узлу, удали.
4. Обнови README узла: добавь созданное в `## Содержимое папки` (`- [file](path) — миссия. Читать: когда`); добавь или обнови маршруты чтения и записи, если созданное вводит устойчивый сценарий; удали соответствующий элемент из `## 🔧 Разворачивание`. Если элемент входит в категорию, сохрани категорию, пока в ней остаётся что разворачивать.
5. Миссию построй по формуле ниже.
6. Создал новый узел (папку) — допиши его строкой в `## Содержимое папки` README родителя.

Без шаблона: обычные папки клиента (`документы/`, `договоры/`) и уникальные узловые шаблоны (напр. `паспорт.md` — лежат шаблоном в самом узле). Нешаблонный md-файл собирается по общей форме: имя — строчные слова через дефис, YAML `title`, H1, аннотация под H1; миссия — по формуле ниже. `AGENTS.md`/`CLAUDE.md` в узле (экспериментальный механизм доставки) — только указание прочитать локальный `README.md`, без локальных правил. Корневые `AGENTS.md`/`CLAUDE.md` — вход агента, не затирать.

Знаки в именах: `_` — только у обзорных файлов и служебных папок (`_входящее/`, `_встречи/`, `_личное/`, `_архив/`), `00_` — только у `00_компания/` и папок управления. Обычным папкам клиент даёт любые имена и номера, кроме `00_` и `_`, и не занимает слова обзорных файлов (`вводная.md`, `делаем.md`, `планы.md`, `хроника.md`, `решения.md`). Нужен ракурс — сразу папка управления, даже ради одного файла. Новое агент называет словом руководителя, по-русски, строчными, слова через дефис, «ё» — как «е».

Профиль сотрудника (`имя-фамилия.md`) — одна форма для всех, включая CEO. Создаётся в `00_команда/` ближайшего объекта, где ведут работу с командой: руководителем — при первом появлении сотрудника с явной ролью (онбординг, первая встреча, первое упоминание) — или самим сотрудником на онбординге.

Встречи размещаются по правилу встреч из корневого README; правило не даёт места → спроси руководителя. Одна встреча — одна папка внутри `_встречи/`, имя и состав — в шаблоне `_встречи/README.md`. Подпапка внутри `_встречи/` — когда встреч много или в одной папке живут несколько серий.

## Миссия файла: формула + заготовки

Формула: **{субъект из имени узла} + {типовая роль файла}**.
Пример: `_делаем.md` в `маркетинг/` → «Маркетинг — что в работе сейчас».

| Файл | Типовая роль |
|---|---|
| `_вводная.md` | самое главное об объекте: что это, кто отвечает, куда идёт и почему |
| `_делаем.md` | что в работе сейчас |
| `_планы.md` | что дальше: план и идеи |
| `_хроника.md` | что происходило |
| `_решения.md` | что решили и почему |
| `видение.md` | идентичность и видение |
| `цели.md` | цели и план периода |
| `стратегия.md` | действующие стратегические выборы |
| `оргструктура.md` | карта ролей и подчинения |
| `имя-фамилия.md` → `иван-петров.md`, в папке сотрудника — `профиль.md` | профиль сотрудника: роль, зона, стиль |
| `ключевые-показатели.md` | ключевые показатели компании |
| `показатели-направления.md` → `показатели-продаж.md` и другие области | показатели области: семантика и источники |
| `паспорт.md` | паспорт сущности: что это по сути |
| `архитектура.md` | как устроено внутри |
| `глоссарий.md` | словарь терминов |
| `speech-aliases.md` | словарь распознавания речи |
| `компания.md`, `люди.md` в папке клиента | бизнес клиента и его люди |
| `процесс.md` → `найм.md` | регламент: как выполняется повторяемая работа |

Служебные папки (`_входящее/`, `_архив/`, `_встречи/`), папка `база-знаний/` и папки управления с README (`00_показатели/`, `00_финансы/`, `00_проекты/`, `00_процессы/`) разворачиваются вместе со своим README — миссия уже в шаблоне, формула не нужна. Простые папки управления (`00_стратегия/`, `00_команда/`) README не имеют: навигируют сами файлы и родитель.

## Правила папки шаблонов

- Папка шаблонов не управленческая: корневые `AGENTS.md` и `CLAUDE.md` пространства лежат в `root/`.
- Шаблон хранится здесь в единственном экземпляре; копии в пространстве не держим.
- Файлы ракурса живут внутри своей папки управления, а не в отдельной общей папке.
- Версия шаблона фиксируется здесь, а не в YAML операционных клиентских файлов.

## Связанные контексты

README шаблонов самодостаточен: всё для разворачивания (механика + заготовки миссий) — выше; связей наружу у папки шаблонов нет.
