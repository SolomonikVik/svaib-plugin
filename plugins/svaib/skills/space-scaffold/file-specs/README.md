# file-specs — спецификации канонических файлов

Перечень канонических файлов пространства и их спецификаций. Канонический файл — файл из этого перечня: у него есть имя, миссия и спецификация.

Перед записью в канонический файл агент читает [общий файл](00_general.md), затем спецификацию этого файла. Нужную спецификацию определяет имя файла, а если имя зависит от предмета — его место.

## Содержимое папки

- [00_general.md](00_general.md) — общий файл: что верно для любого канонического файла.
- [overview.md](overview.md) — `_вводная.md`: самое главное об объекте — что это, кто отвечает, куда идёт и почему.
- [active.md](active.md) — `_делаем.md`, текущая работа.
- [backlog.md](backlog.md) — `_планы.md`, будущая работа.
- [progress.md](progress.md) — `_хроника.md`: что происходило с объектом и когда.
- [decisions.md](decisions.md) — `_решения.md`, журнал решений.
- [meeting-summary.md](meeting-summary.md) — `саммари.md` в папке встречи, саммари встречи: где она лежит; форму задаёт спецификация разбора встречи.
- [reference.md](reference.md) — `employee.md`, `профиль.md`, `паспорт.md`, `архитектура.md`, `глоссарий.md`, `speech-aliases.md`: общие правила справочных файлов; структура каждого — из его шаблона.

## Подключить спецификацию к хуку

Положи спецификацию в эту папку отдельным `.md`-файлом. В YAML-шапке укажи `title`, `status` и `file_patterns` — непустой JSON-массив масок на одной строке:

```yaml
---
title: "Тип example — миссия файла"
status: draft
file_patterns: ["_example.md", "_meetings/*/example.md"]
---
```

- Маска без пути действует в любом узле. Маска с `/` совпадает с концом пути от корня пространства: `_встречи/*/example.md` подходит и для `sales/_встречи/2026-10-10_sync/example.md`.
- `*`, `?` и `[]` работают внутри одной части пути; `*` не охватывает несколько папок. Регистр не учитывается. Абсолютные пути, `.`/`..`, обратные слеши и `**` запрещены.
- Пока живые пространства не переехали на новые имена, прежнее имя задаётся второй маской: `"_делаем.md"` и `"[0-9][0-9]_active.md"`. `?` означает ровно один символ, а не необязательную часть.
- Если подходят несколько спецификаций, хук выдаёт все. Общий файл `00_general.md` приходит первым; `README.md` этой папки не является спецификацией типа.
- Новые файлы и изменения масок видны при следующем запуске хука, в том числе в текущей сессии. Текст каждой спецификации подаётся один раз за сессию, после сжатия — снова.
- Файлы вне пространства, скрытые папки, `_templates/`, `_архив/`, `node_modules/` и `scaffold/templates/` исключены независимо от масок. Сами спецификации хук тоже не перехватывает.

Хук читает только эту папку и не выводит маски из текста или имени спецификации. Каталог спецификаций поставляется целиком; Python-код и манифест для нового типа менять не нужно. Спецификация без корректного `file_patterns` останавливает сборку пакета. При повреждении уже установленной спецификации хук пишет причину в лог и продолжает работать с остальными.

Профиль с произвольным именем распознаётся также по месту и шапке: файл `.md` под `00_команда/` (до переезда — и под `00_команда/`) с полем `role` или `units`, кроме файлов во встречах, служебных и датированных папках. При создании через `Write` шапка берётся из текста записи, при изменении — из существующего файла. Такой профиль получает ту же спецификацию `reference.md`. Дополнительные каноны вне этой папки автоматически не подключаются.
